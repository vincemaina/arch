## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A new machine needs an SSH key generated by hand, loaded into an agent, and registered with GitHub before anything can be pushed from it. That is a step remembered badly and at the worst moment, because it is only needed the first time a change leaves the new machine.

There are three separable pieces here, and they do not have to be answered the same way.

Key generation. Whether the build generates a key on first boot, or whether a key is carried between machines deliberately. Per-machine generation is better hygiene and keeps anything secret away from this repository entirely; it also means every new machine has to be registered somewhere before it is useful.

The agent. Something has to hold the unlocked key for the session, and on this system that means a user unit - territory this repository already understands. The existing rules apply unchanged: bound to wayland-session@sway.target rather than the generic graphical target, and Restart=always. Candidates worth pricing against each other: plain ssh-agent under systemd, gcr, or gnome-keyring.

Registration. The gh CLI can upload a public key with gh ssh-key add, which would close the loop without a browser. But gh has to be authenticated first, which is the same bootstrapping problem one level up, so it may solve less than it first appears to.

One hard constraint rather than a trade-off: no private key material goes into this repository in any form, ever. Any design needing it is out of scope by definition.

Raised as an idea rather than a request. Needs discussing before anything is committed to.
