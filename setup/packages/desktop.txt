# Virtual machines, for isolating dangerous work or a project from the machine
# you are sitting at. Driven by ~/.local/bin/vm; see TASK-69 and DECISIONS.md.
#
# Deliberately qemu on its own rather than libvirt and virt-manager. Both run
# the same qemu process with the same guest RAM, so the guest costs the same
# either way and the difference is only scaffolding: roughly 30 MiB for a
# kiosk compositor against 140 MiB for libvirtd plus virt-viewer, or 250-330
# MiB once the virt-manager GUI is open. That saving is second-order next to a
# 2-4 GiB guest and is NOT the reason. The reasons are fewer moving parts - no
# daemon, no XML domain definitions, no libvirt group - and skipping the SPICE
# round trip, since qemu can present straight to a Wayland surface. What
# libvirt would have bought is snapshots, and qcow2 overlays give most of that
# for free.
#
# qemu-system-x86 is the emulator; qemu-img creates and clones the disks.
qemu-system-x86
qemu-img

# The guest's graphics card. These are SEPARATE packages from qemu-system-x86 in
# Arch, which is worth knowing before debugging: without them qemu starts and
# then dies saying it does not know the device, and the configuration naming it
# looks perfectly correct.

# virtio-vga-gl is what ~/.local/bin/vm asks for first, and it is what makes a

# qemu-common and would give a GL device with nothing behind it.
#

# warning, so a machine that skips them still runs guests. It just runs them
# without acceleration.
