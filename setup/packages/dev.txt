# "Where did the disk go". dust ranks the biggest directories anywhere in a
# tree in one word, where du needs a --max-depth guessed in advance and a
# sort/tail pipeline after it - and the guess is what hides the answer. On this
# machine `du -sh ~/*` shows .local at 1.4G and stops; dust names the three
# cached Claude Code versions inside it, 969 MiB and 46% of home, without being
# asked to look. Faster too: 126-134 ms against 217-219 ms for the du pipeline
# over /usr, warm cache, three runs each.
#
# Nothing already installed does this: btop reports filesystem free space, not
# per-directory, and yazi has no size command at all - checked against the
# defaults extracted from its binary, not from memory. In extra, 2.97 MiB,
# depends on nothing but glibc and libgcc. See TASK-49.
dust

# Git, beyond commit and push. Reached from the launcher and from
# ~/.local/bin/git-ui, which opens it on the repository the focused window is
# standing in.
#
# The complaint in TASK-45 was not that git is missing, it is that the bare CLI
# is poor at four things this repository does constantly: reading a diff before
# committing, staging part of a file, seeing what changed across a session, and
# resolving a conflict. All four were tried against a clone of this repository
# rather than judged from a feature list.
#
# Staging part of a file is the one that decided it. `git add -p` asks
# "(1/3) Stage this hunk [y,n,q,...]?" and you answer before you are allowed to
# see hunks two and three; lazygit shows all three at once and stages the one
# under the cursor with <space>. Measured on a three-hunk edit to
# checks/session.sh: six keypresses and a message produced a commit containing
# exactly hunk one, with the other two still unstaged.
#
# Conflicts settled whether a separate merge tool was also wanted. It is not.
# A real conflicting merge in the clone was resolved with one keypress - the
# footer offers "Pick hunk: <space> | Pick both hunks: b | Next conflict:
# <right>", the markers were gone afterwards and the file was staged. meld,
# 5.64 MiB and a GTK window, would have been the alternative and does less on a
# keyboard-driven desktop.
#
# 19.07 MiB, the largest of the three TUIs, and the size is the honest cost.
# tig is 702 KiB and reads well but stages badly - its status view is one pane
# showing filenames with no diff until you press enter. gitui is 8.09 MiB and
# closer, but shows an empty diff pane until you select a file where lazygit
# arrives with the diff, the log and the branches already on screen. Startup is
# around a second against a few milliseconds for `git status`, which is the
# other real cost.
#
# git-delta is NOT here yet, and that is deliberate rather than an omission. It
# is the cheap answer to half of this - a pager that makes `git diff` readable,
# 4.96 MiB - but it is configured in a gitconfig, and this repository has no
# gitconfig at all until TASK-37 decides whether it should. Adding it here would
# mean inventing a second home for git settings. It composes rather than
# competes: lazygit ships explicit delta support, so TASK-37 can add it to both
# at once. difftastic was ruled out on size: 113.99 MiB, six times lazygit.
lazygit

neovim

# Node, for the language servers that exist only as npm packages.
#
# html, css, json and emmet have no server in the official repositories. The AUR

# because those particular packages are among the least maintained things in it:
# vscode-langservers-extracted has four votes and was last touched in May 2024,

#
